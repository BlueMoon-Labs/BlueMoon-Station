# Миникарты NanoMap

Используется тот же генератор, что в SS1984: [ParadiseSS13/SpacemanDMM-Para](https://github.com/ParadiseSS13/SpacemanDMM-Para), релиз `suite-1.11-P`. SHA-256 Linux-бинарника совпадает с `tools/github-actions/dmm-tools-para` исходного билда. Исходники и GPL-3.0 доступны в репозитории генератора.

Штатная сборка обновляет миникарты при изменениях карт, их конфигурации, DM-кода или спрайтов. Отдельная команда:

```text
node tools/build/build.js nanomaps
```

Для принудительного обновления всех миникарт:

```text
node tools/nanomaps/render.cjs
```

При первом запуске подходящий для Windows или Linux бинарник загружается в `tools/bootstrap/.cache/nanomaps/`. Контрольная сумма проверяется перед каждым запуском. Генератор получает все карты из корневых конфигураций `_maps/*.json`, включает проход `nanomaps`, отключает `icon-smoothing` и создаёт по восемь пикселей на тайл. Имена ассетов учитывают полный путь карты; её собственные размеры и число этажей определяются через `map-info`.

Изображения находятся в `icons/_nanomaps/`, список ресурсов и размеры — в `code/modules/asset_cache/assets/nanomaps.dm`. PNG дополнительно пересжимаются без изменения пикселей. Эти файлы должны попадать в коммит вместе с изменениями генератора или карты, чтобы готовые миникарты были доступны и без загрузки инструмента. Глобальные Z-номера назначаются только при загрузке мира; подписи этажей вычисляются отдельно, по связям Look Up/Look Down.

Старая раскраска зон сохранена в `/datum/minimap/New()` и выключена по умолчанию параметром `area_colors = FALSE`. Настройки цветов у зон и объектов сохранены. Крю-монитор использует готовые PNG без растеризации на сервере. Метаданные зон для подсказок обычной OOC-миникарты строятся отдельно, при её первом открытии.
