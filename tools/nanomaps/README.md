# Миникарты NanoMap

Используется тот же генератор, что в SS1984: [ParadiseSS13/SpacemanDMM-Para](https://github.com/ParadiseSS13/SpacemanDMM-Para), релиз `suite-1.11-P`. SHA-256 Linux-бинарника совпадает с `tools/github-actions/dmm-tools-para` исходного билда. Исходники и GPL-3.0 доступны в репозитории генератора.

Штатная сборка обновляет миникарты при изменениях DMM-карт, их конфигураций `_maps/*.json`, DMI-спрайтов, настроек `SpacemanDMM.toml` или генератора `render.cjs`. Обычные изменения DM-кода и списка включений DME не запускают генерацию PNG: правки сообщений, проков и интерфейсов больше не добавляют время рендера к каждой компиляции. Отдельная команда с той же проверкой актуальности:

```text
node tools/build/build.js nanomaps
```

Для принудительного обновления всех миникарт:

```text
node tools/nanomaps/render.cjs
```

Принудительная генерация требуется, если меняется исходная внешность типов в DM: например, `icon`, `icon_state`, `dir`, `color`, `alpha`, `layer`, `plane`, смещения или наследование этих параметров, а также влияющие на них дефайны и включения DME. Штатная проверка не разбирает семантику DM и такие изменения автоматически не обнаруживает. PNG остаются локальными результатами сборки; если изменился список ассетов, обновлённый DM-манифест нужно включить в коммит. Изменения серверной маски отделов и динамических дополнений карты сами по себе не требуют пересоздания статических PNG.

При первом запуске подходящий для Windows или Linux бинарник загружается в `tools/bootstrap/.cache/nanomaps/`. Контрольная сумма проверяется перед каждым запуском. Генератор получает все карты из корневых конфигураций `_maps/*.json`, включает проход `nanomaps`, отключает `icon-smoothing` и создаёт по восемь пикселей на тайл. Имена ассетов учитывают полный путь карты; её собственные размеры и число этажей определяются через `map-info`.

Изображения находятся в `icons/_nanomaps/`, список ресурсов и размеры — в `code/modules/asset_cache/assets/nanomaps.dm`. PNG дополнительно пересжимаются без изменения пикселей и исключены из Git через `.gitignore`; текстовый DM-манифест отслеживается. Штатная сборка проверяет наличие каждого PNG из манифеста, поэтому в чистой копии репозитория или при потере изображения генерация запускается автоматически. CI создаёт изображения также перед линтерами и DreamChecker. Первый запуск требует доступ к загрузке рендерера, если его ещё нет в локальном кэше. При прямой компиляции через Dream Maker сначала выполните команду генерации; предпочтительна штатная сборка `tools/build/build`.

Для перехода с отслеживаемых PNG используется `git rm --cached -- icons/_nanomaps/*.png`: файлы остаются на диске, а следующий коммит прекращает их отслеживание. Переписывать старые коммиты не нужно; старые версии PNG сохраняются в истории Git. Не используйте `git add -f` для этих изображений. Глобальные Z-номера назначаются только при загрузке мира; подписи этажей вычисляются отдельно, по связям Look Up/Look Down.

Старая раскраска зон сохранена в `/datum/minimap/New()` для вызовов без исходного PNG. При наличии NanoMap параметр `area_colors = TRUE` добавляет маску цветов зон с непрозрачностью 50%. Маска однократно строится на сервере по загруженным станционным полам и масштабируется до размера PNG. Космос, открытые пространства, природные покрытия (включая песок, астероид и снег), наружные зоны, стены и объекты, блокирующие атмосферу, не окрашиваются; двери и окна на стороне тайла исключены из этой проверки. Крю-монитор переключает обычный и цветной фон галочкой «Отделы», выключенной по умолчанию; сами PNG в `icons/_nanomaps/` остаются исходными NanoMap. Метаданные зон для подсказок обычной OOC-миникарты строятся отдельно, при её первом открытии.

Полнотайловые окна дополняются спрайтами загруженной карты после штатного сглаживания. Выбор отдельного спрайта выполняет общий `/atom/proc/get_minimap_icon()`. Тип может задать `minimap_icon` и `minimap_icon_state`. Необязательный аргумент типа источника позволяет брать настройки исходного DMM, даже если генерация изменила турф. Игровая отрисовка камней не меняется.

Геометрия камней и допустимые позиции дверей берутся из того же исходного DMM через штатный /datum/parsed_map: изменения пещер и шаттлы отдельного запуска не смешиваются со статической основой NanoMap. Решётки /obj/structure/lattice дополняются итоговыми спрайтами после сглаживания.
