учтены изменения `b38aa6b604`, `1ddaee105c`, переход к графу APC/реле и переработка canvas,

подтверждённое прохождение сборки, автоматического теста или проверки в игре.

## Переход к графу

| Проверяемое свойство | Реализация | Граница |
|---|---|---|
| Один endpoint — один APC | Стабильный `bound_apc`, nearest-поиск при изменении контекста; обнаружение APC, созданного после endpoint | APC вне сектора не участвует; отсутствие APC не создаёт фиктивных связей |
| Связный сектор | `NETRUN_APC_NEIGHBORS` ближайших APC (сейчас 3) и кратчайшие мосты между компонентами | Геометрия определяет отображение, структуру и задержку физического ребра |
| Межсекторная связь | Реальное реле связано с одним APC; любые два настоящих реле образуют шлюзовой переход | Нужны действующие реле с обеих сторон и включённый NTnet |
| Отказ инфраструктуры | Структурная связь сохраняется, но offline-вершина не пересылает запрос | Недоступная конечная вершина может отображаться как лист для диагностики; это не право управления |
| Серверные маршруты | Периодическая сверка новых/движущихся узлов и таблиц путей активных карт; постоянная подсветка пути до выбранной цели | Снимок обновляется раз в секунду; реальные запросы проверяют живой путь отдельно, неиспользуемые таблицы удаляются |
| Обзор и перемещение | Секторная географическая карта, Ping и hop используют один физический граф | Полнота обзора не заменяет проверки прав; сущность переходит только на одно ребро |
| Ключи и учётные данные | Ключ ЛВС даёт гостевой вход и перемещение; `access` содержит скопированные реальные ID-доступы для действий | ROOT-извлечение только из ID носителя/нейроendpoint и реальных RFID-слотов; требования машины не копируются |

## Общие условия расширения

Узел — компонент на атоме. Команды, CLI, демоны и API задаются подтипами с метаданными.
Для динамических возможностей есть `netrun_extra_commands()`, для особых окон — реальные
`netrun_window_*` хуки, для личного доступа — `netrun_owner_access()`.
Клиенты и нейроинтерфейсы подключаются отдельными компонентами, а не новым набором веток
общего switch. Описание контрактов и текущего охвата находится в [README](README.md).

Запросы проходят проверку доступа и маршрута, а затем используют штатную механику цели.
Публикация API не отключает проверку ресурсов, исследований, оплаты, блокировки или
специальных условий `emag_act`. Отдельный особый GUI всё ещё может потребовать собственной
TGUI-реализации.

В модуль добавлены регрессионные сценарии для контекста команд/окон, файлов/ёмкости,
копирования фото/weakref, пикселей/видимости/печати снимков, повторной проверки доставки,
выбора UID, API whitelist, нейроинтерфейсов/шрифта, оптики/жизненного цикла видеопотоков,
pAI и реестра демонов. Для графа добавлены сценарии порядка инициализации, стабильности
привязки, смены области/сектора, удаления APC, связности ближайших соседей и мостов, отказа реле с каждой стороны,
локальных межэтажных путей, полноты обзора, стоимости рёбер и соседства переходов сущности.
Сценарии серверных таблиц проверяют независимость копий, обновление после отказа APC,
перенос вложенной цели к новому APC и удаление таблиц неактивных карт.
Отдельно описаны порядок mapload-привязки и отсутствие утечки CLI-дополнений после отзыва ключа.
Для учётных данных добавлены реальные ID-слоты/ношение, снимки и независимые копии,
ёмкость/отсоединение шарда, native `allowed()` и правило «ключ разрешает hop, но не управление».
Для боя добавлены сценарии подготовки/прерывания ICE, щита, независимых кулдаунов,
настоящих встроенных программ, получения демонов и нехватки памяти. Для автовзлома —
ожидание до награды, отмена, отзыв программы; в UI — прогресс, предупреждение во время
головоломки и восстановление добычи. Новые сценарии охватывают полный обзор за пределами
четырёх рёбер, добавление/удаление/отключение узлов, прямую привязку к APC внутри области,
ответную атаку до ГОСТЬ, утрату боевого контакта, владение файлами и заимствованным шардом,
освобождение dive link и отмену пакета при удалении зависимости. Canvas проверяется на
плотных графах, сохранении позиций и камеры, вписывании и пересечении подписей.
Само наличие тестов не означает успешный прогон: результаты компиляции, автоматического
запуска и визуальной проверки игрового клиента фиксируются отдельно.


Дополнения аудита: полиморфные задачи и условные провайдеры, стабильная строка
атаки ICE, отменяемый автопроход, минимальные мосты компонентов и атмосферные
сервисы описаны в [README](README.md). Воспроизводимый запуск тестов и
интерактивные сценарии — в [DEVELOPMENT.md](DEVELOPMENT.md). Новые настройки
числа соседей и географической задержки проверяются через масштабированные
сценарии; тесты не требуют возвращать прежние значения констант.
