# Провайдеры игровых механик

Провайдер публикует ограниченный сетевой сервис конкретного игрового объекта.
Контракт находится в `core/providers.dm`, адаптер штатного TGUI — в `core/api.dm`,
атмосферные сервисы — в `integration/atmospherics.dm`.

## Контракт и выбор

| Часть | Назначение |
|---|---|
| `atom_type` | Статический тип подходящих объектов |
| `priority` | Приоритет сервиса; при равенстве побеждает более конкретный тип |
| `state_signals` | Сигналы изменения состояния самого атома; нужны для обновления тихой карты |
| `available(target)` | Текущее условие публикации: провода, установленный компонент, состояние сборки |
| `actions` | Белый список действий, уровень доступа, описание, опасность, схема параметров |
| `action_unavailable_reason(...)` | Причина недоступности конкретного действия либо `null` |
| `read_data(...)` | Новый список данных для панели устройства |
| `execute(...)` | Полиморфная доставка проверенного действия |

`SSnetrun.get_provider(target)` выбирает один действующий сервис. Реестр автоматически
находит подтипы `/datum/netrun_provider` с заданным `atom_type`. `get_api()` сохранён
для совместимости. Кеш по типу хранит список кандидатов; `available()` проверяется
на самом объекте при каждом выборе. Отключение сервиса одного насоса не отключает
все насосы того же типа и не требует сброса глобального кеша.

Узел подписывается на `state_signals` **всех статических кандидатов**, даже если
сервис недоступен при создании. Иначе появление контроллера или восстановление
провода не разбудит отключённый сервис. Подписками владеет компонент узла и
снимает их при удалении. Обработчик только ставит `pending_state_notification`
и добавляет узел в очередь; сериализация и уведомление карты выполняются позже.

Штатные адаптеры слушают `COMSIG_UI_ACT` и `COMSIG_ATOM_UPDATED_ICON`. Старые
насосы обходят `/atom/update_icon()`, поэтому атмосферная интеграция публикует
`COMSIG_NETRUN_SERVICE_STATE_CHANGED` после своего нативного обновления иконки.
Этот же сигнал покрывает провода сигнализации и их таймеры восстановления.
Новая механика с собственным сигналом добавляет его в `state_signals` провайдера.

Провайдеры общие для раунда. Не храните в них оператора, текущую машину, выбранный
файл, результаты последнего запроса или другие изменяемые данные сеанса. Такое
состояние принадлежит машине, компоненту или объекту сеанса. Методы выбора и
проверки условий должны быть дешёвыми и не должны менять игровой мир.

## Публикация штатного интерфейса

Добавьте объекту `/datum/component/netrun_node`, задав его тип, команды, защиту и
нужные ID-доступы. Затем создайте подтип `/datum/netrun_api`:

```dm
/datum/netrun_api/example
	atom_type = /obj/machinery/example
	interface_name = "Example"
	actions = list(
		"power" = list("name" = "Питание", "access" = NETRUN_ACCESS_USER),
	)

/datum/netrun_api/example/available(atom/target)
	if(!..())
		return FALSE
	var/obj/machinery/example/device = target
	return device.controller_installed
```

`example` — шаблон для существующего типа машины; этот пример не входит в сборку.
Новый `.dm` включается в `tgstation.dme`. Не добавляйте проверки нового типа в
консоль, реестр или общий `remote_request()`.

`/datum/netrun_api` получает данные через штатные `ui_static_data()` и `ui_data()` и
передаёт только опубликованные действия в штатный `ui_act()`. ID-права, оплата,
материалы, исследования и другие проверки самой машины продолжают действовать.
Сетевой запрос не выдаёт оператору привилегии силикона.

Схема параметра поддерживает `id`, `name`, `type` (`text` или `number`), `min`, `max`.
Все параметры схемы обязательны. Числа проверяются как конечные значения с
включительными границами; нулевая граница не заменяется значением по умолчанию.
Лишние параметры отбрасываются. Внутри провайдера числа приходят числами.

Некоторые старые `ui_act()` ожидают строку даже для числа и вызывают `text2num()`.
Для них задайте параметру `native_text = TRUE`: числовая валидация сохраняется,
а непосредственно перед штатным вызовом число превращается в строку. Остальные
машины, например фабрикаторы, продолжают получать число.

Действие может задавать серверные `native_action` и `fixed_params`: например,
кнопка «Фильтрация» вызывает `mode` с фиксированным идентификатором режима.
Клиент не может заменить этот идентификатор своими аргументами. В панель уходят
пользовательские названия, описания и ограничения, а не поля диспетчеризации.

Если механика не имеет `ui_act()`, наследуйтесь непосредственно от
`/datum/netrun_provider`, реализуйте `read_data()` и `execute()`. Возврат `TRUE` из
`execute()` означает принятую доставку; завершение длительной операции должно
отображаться самой механикой. Общий маршрут, журнал и трассировка сохраняются.

## Границы доставки

Маршрут, текущая ЛВС, оператор, блокировка сеанса и уровень доступа проверяются
перед отправкой и при доставке. При доставке дополнительно проверяется, что
выбран тот же провайдер, сервис доступен и параметры всё ещё подходят его схеме.
Запрос к отключённой возможности отменяется, а не переадресуется другому сервису.
Даже внутренний `do_remote_request()` проходит проверку схемы при доставке.

Нативный контекст `/datum/ui_state/netrun_request` проверяет уровень именно
вызванного действия: ожидающий ROOT-вызов не сохраняет права после снижения до
USER. Проверки конкретного игрового состояния добавляются полиморфным методом
`action_unavailable_reason()`. Причина попадает в интерфейс и повторно проверяется
при доставке; запрет только на стороне TGUI недостаточен.

## Атмосферные сервисы

Воздушная сигнализация, насос давления и объёмный насос получают узел типа
`atmos` с `ACCESS_ATMOSPHERICS`. Насосы публикуют питание и уставку в своих единицах
(кПа и л/с). Используется штатный `ui_act()`, включая журнал расследований,
ограничения и пробуждение спящего атмосферного обработчика.

Режимы сигнализации берутся из `GLOB.air_alarm_modes`: названия, описания,
опасность и условие модифицированной прошивки остаются общими с физической
панелью. Обычные режимы требуют USER, опасные — ROOT. Программная блокировка
панели сохраняется; её можно открыть ID на месте либо явной ROOT-командой
`atmos_lock`. Эта команда не чинит перерезанные провода ID или управления.
Отключённое управление снимает сервис, а разобранная или закороченная
сигнализация не отвечает по сети.

## Проверки

`integration/machine_services.dm` добавляет SMES (вход USER, потенциальное отключение выдачи ROOT), пожарную сигнализацию (тревога USER, сброс ROOT с сохранением физических блокировок) и кухонную печь (еда/выгрузка USER, рискованные предметы ROOT). Команды `smes_status`, `fire_status`, `microwave_status` дают GUEST полезную диагностику; управление использует штатные клампы, провода, питание, цикл приготовления и журналы машин. Эти сервисы не разрешают универсальную атаку прошивки.

`code/modules/unit_tests/netrun_providers.dm` покрывает независимые условия двух
объектов одного типа, восстановление сервиса при прогретом кеше, отзыв сервиса
у пакета в полёте, полиморфное выполнение без TGUI, схему внутренних запросов,
границы чисел, отзыв ROOT у нативного контекста, оба настоящих насоса и режимы
настоящей сигнализации. Тесты используют прямую доставку управляемого пакета
без ожидания игровых таймеров. Команды общего запуска приведены в README модуля.
