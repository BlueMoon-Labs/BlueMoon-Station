# ID погружения и ключи добытых прав

При погружении настоящий список доступов ID тела один раз сохраняется в приватный файл `dive-id.access`. Пока длится это погружение, смена или извлечение физической карты не меняет снимок. Новый доступ тела появится при следующем погружении. Снимок виден среди файлов с источником «сессия»: его можно удалить, немедленно отозвав эти ID-права до выхода.

Сессионный файл не попадает на общий диск импланта, не копируется, не перемещается на шард, не загружается в узел и не предлагается другому процессу. Возврат, потеря тела или уничтожение связи удаляют его. Обычные `.access`, отдельно извлечённые из реального ID-источника командой `extract_credentials`, сохраняют свои прежние правила хранения.

Результаты взлома автоматически пополняют один обычный переносимый файл `acquired.grants`. Для него нужна одна ячейка: она проверяется до начала подбора, без скрытых прав при заполненной памяти. Автовзлом узла записывает USER, взлом шлюза — GUEST; ручной взлом сохраняет фактический уровень награды. Права стартового проживания, ID, пароли серверов и состояние взломанной прошивки в ключ не входят.

Ключ работает только пока его реальный файл находится в памяти или подключённом шарде. Он повышает эффективные сетевые права, но не легальный ID-доступ и не проходит нативный `allowed()` машины. Его использование не записывает права навсегда в новую сессию: файл можно копировать обычным способом, а удаление последнего источника немедленно отзывает его эффект.

На каждом носителе файлы `.grants` автоматически объединяются при получении, копировании или импорте. Сохраняются UID существующего файла и максимальные действующие права; повторяющиеся записи не занимают новые ячейки. Локальная память и съёмный шард — разные носители: копия на шарде остаётся самостоятельной и её можно отдать. Обычные ID-файлы `.access` не смешиваются с добытыми сетевыми правами.

Каждая область ключа привязана к исходному объекту, сети и её текущему ключу. Поднятие сетевого экрана отзывает все старые копии права на этот узел; смена привязки узла или ротация ключа ЛВС также делает соответствующие области недействительными. Копирование и объединение сохраняют исходные метки отзыва: устаревший файл не оживляет права. Для обновления соответствующей записи нужно действительно получить доступ заново.

Запись награды использует `record_breach_grant()` и реальный файл: нативный взлом не создаёт параллельный постоянный грант в таблицах сессии. `snapshot_acquired_key()` копирует действующие области с исходными метками, в том числе для агента. Совместимые внутренние гранты без доказанного результата взлома не экспортируются. Интерфейс показывает файл и позволяет сохранить копию на выбранный носитель.
