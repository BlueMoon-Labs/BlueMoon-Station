# Разбор нагрузки Netrun

Исходная ветка: `net-feature`, PR #4257, исходный commit
`1805d8935d0a02d3bc87f36cb033bc2a5d9835ad`.
Разбор опирается на два приложенных снимка профайлера и проверку серверных
цепочек вызовов. Числа ниже относятся к исходным снимкам, а не к новому замеру.

## Цепочки, которые создавали лишнюю работу

1. Запись о пакете ставила узел на обработку. Обработка читала его питание,
   защиту и физический контекст, затем публиковала изменение. Каждый открытый
   интерфейс получал отдельный сигнал и мог снова поставить свою консоль в очередь.
   Локальные сигналы также достигали зависимых нейролинков.
2. Почти любое фоновое событие ставило `ui_event_pending`. Задача консоли
   воспринимала это как повод обойти интервал перерисовки. Общий CPU-бюджет
   ограничивал проход, но не устранял повторную подготовку одной картины сети.
3. Проверка узла вызывала проверку ЛВС, получение маршрута и получение ID/ключей.
   Вне активного `ui_data` получение пути делало собственную копию всего дерева.
   Автодополнение повторяло проверку ЛВС для каждого адреса.
4. При двух пользователях одного терминала менялся `operator`. Единственная
   сохранённая проекция карты постоянно перестраивалась под очередного пользователя.
   Сравнение наблюдаемого набора ID также зависело от порядка пользователей.
5. Выбор узла/waypoint мог попасть в общий путь пересборки карты. События в другом
   сегменте поддерживали перерисовку через глобальную ленту событий.
6. Все консоли сетевых сущностей считались активными всегда. Постоянные охотники
   патрулировали пустые ЛВС и создавали новые движения, журналы и уведомления.

## Изменения

### Публикация и фоновые обновления

- Узлы накапливают `address => merged_flags`. На границе прохода SSnetrun
  отправляется один `COMSIG_NETRUN_NODES_CHANGED`, а не отдельный UI-сигнал
  на каждую запись/фазу пакета. Повторения одного адреса объединяются.
- Консоль и карта обрабатывают весь пакет и вызывают `invalidate_ui()` один раз.
  Для `E` событий, `D` уникальных адресов и `V` интерфейсов число глобальных
  UI-колбэков уменьшается с порядка `E × V` до `V` на публикацию. Проверки
  принадлежности изменённых адресов остаются порядка `D × V`; это не полный обход
  карты и не повторный запуск маршрутизации.
- Игровые зависимости узла и доступность для машинных сервисов остаются живыми.
  Фоновая публикация не является источником авторизации команды.
- `NETRUN_CHANGED_DETAILS` отделяет журналы/содержимое диска от состояния карты.
  Эти изменения не запускают обработку узла, чтение питания и проверку нейролинка.
  Без интереса к узлу журнал вообще не создаёт публикацию; последующее открытие
  панели читает актуальный ограниченный журнал напрямую.
- Повторный `touch()` продлевает время активности без повторной публикации
  неизменившегося признака «активен». Исходящий кадр отправляется при первом
  касании и при последующем истечении активности.
- 15 проверенных диагностических команд помечены `read_only`: чтение журналов,
  scan/ping/traceroute и отчётов больше не объявляет машину изменившей питание
  после каждого чтения. Изменяющие команды по умолчанию сохраняют прежнюю проверку.
- Уведомления журналов ЛВС также объединяются на границе прохода.
- Фоновая перерисовка соблюдает `ui_refresh_interval`. Явный ввод игрока сохраняет
  немедленный ответ. Грязная консоль не создаёт цикл повторных задач в одном тике.

### Маршруты и доступ

- Синхронные чтения используют заимствованную таблицу физических путей.
  Получение отдельного дерева сохранено для операций с собственным временем жизни
  и возможным ожиданием. Свежие проверки переходов и ICE обходят UI-снимок.
- Проверки пути продолжают читать живую доступность APC/реле. Права не помещаются
  в общий физический кеш и не передаются другому оператору.
- В одном `ui_data` доступ к ЛВС, ключи, легальный доступ и уровни узлов вычисляются
  повторно только после инвалидирования. Это относится и к явно переданному
  дереву, когда оно является деревом текущей сериализации UI.
- Автодополнение вычисляет уровень одной ЛВС один раз на проекцию, независимо
  от числа её конечных узлов. Вложенная проверка узла использует одно дерево
  вместо повторного разрешения физического источника.
- Алгоритм построения дерева проверяет онлайн-состояние установленного
  промежуточного узла один раз, вместо проверки на каждом исходящем кабеле.
  Для звезды «APC + 48 конечных устройств» это 1 чтение состояния APC вместо 50
  при расчёте от APC. Это подсчёт операций по коду, не результат бенчмарка.
- Проверка цепочки проверяет каждый промежуточный узел один раз. Состояния реле
  переиспользуются только внутри одного синхронного расчёта.
- Машинные пакеты не вызывают `join_network()` для неизменившихся привязок;
  обработчики движения/вложенных контейнеров и поколение инфраструктуры отмечают
  действительную необходимость перепривязки.
- Внутри одного тёплого обращения машинного транспорта уже проверенные источник,
  получатель и их APC не проверяются снова на каждом ребре. Для пути
  «источник → APC → APC → получатель» это 4 чтения состояния вместо 12.
  После вызовов, которые могут опубликовать новый контекст, проверки повторяются.
- Ограниченная беспроводная точка не рассчитывает всю станцию, чтобы затем
  удалить все удалённые адреса из результата.
- Удаление источника немедленно освобождает его сохранённое дерево маршрутов.
  Очистка устаревших таблиц не опрашивает инфраструктуру сама по себе.

### Карта и несколько пользователей

- Один терминал сохраняет проекции разных операторов раздельно. После первого
  построения переключение между ними восстанавливает кеш и журнал дельт.
  Общие навигация и гранты сеанса сохраняют прежнюю семантику.
- Число сохранённых проекций ограничено 8; неактивные записи старше 5 минут
  удаляются при обслуживании кеша. Закрытая/скрытая карта освобождает припаркованные
  проекции. Равные неизменяемые записи узлов/рёбер разделяются между пользователями;
  словари видимости и проверки прав у каждого свои.
- Изменения доступа, инвентаря, топологии и видимых узлов помечают также
  припаркованные проекции. После возврата к пользователю права снова сверяются.
  Поколения потока не позволяют применить дельту к чужому/старому UI-снимку.
- Выбор узла и waypoint обновляют раскрытие маршрута и выбранную APC-зону
  без пересборки всех конечных устройств.
- Событие поддерживает анимацию только у карт, показывающих его конец или сегмент
  пути. Истечение эффекта считается от времени события, не от открытия карты.
- Равные ссылки на неизменяемые списки сравниваются сразу, без рекурсивного обхода.
  Геометрия области APC кратковременно разделяется между зрителями; исходный срок
  годности не продлевается новым зрителем, идентичность области проверяет weakref.

### Неактивные процессы и удаление устройств

- Здоровая сущность без клиента и нейронного тела не входит в периодическую
  обработку. Сигнал движения её собственного узла сохраняет физическое положение;
  вход клиента и повреждение пробуждают процесс. Таймеры навигации имеют владельца.
- Постоянный патруль пустой ЛВС спит. Появление сущности или взлом пробуждает
  защиту этой ЛВС. Одно открытие общей карты не запускает патрули всей станции.
- Подвижная машина с нативными сигналами не получает дополнительный опрос только
  из-за возможности двигаться. Fallback для действительно старых полей остаётся.
- Удаление деки уже удаляло консоль и отменяло зависимые готовые/отложенные запросы;
  отдельного бесконечного процесса в этой цепочке не найдено. Устранены фоновые
  источники активности и удержание таблицы удалённого источника.

## Повторный профиль и CI

Второй профиль включает загрузку мира: около 270 тысяч `InitAtom` и 243 тысяч
`join_network` нельзя считать стоимостью устойчивой работы открытой карты.
Оценивать сокращение вызовов нужно по разнице счётчиков после завершения загрузки.

- Пустой worker обслуживается раз в 20 децисекунд вместо 2. Приём готовой задачи
  пробуждает его сразу; очередь продолжает исполняться в прежних бюджетах. Активные
  консоли и временные состояния сохраняют свои ближайшие сроки. Минимальный срок
  узлов поддерживается при существующих обходах, без нового сканирования станции.
- Нормализация настроек и перестройка приоритетов выполняются только при реальном
  изменении значений, включая изменение самого списка приоритетов.
- Холодные деревья разных источников делят одну проверку доступности APC за тик.
  Живая проверка источника, якорей и посещённых промежуточных узлов остаётся; найденные
  изменения поколения применяются до сохранения дерева. Обработчики уведомляются
  после завершения обхода, поэтому не меняют граф посередине Dijkstra.
- Предпросмотр пакета обходит рекурсивно только вложенные контейнеры. Неизменившийся
  маршрут сохраняет собственный список. Последний получатель рассылки получает
  исходное сообщение, остальные — независимые копии: одноадресная доставка обходится
  без дополнительного глубокого копирования сообщения.
- Восстановление карты принимает подтверждение действительно отправленного полного
  снимка, даже если сервер уже отправил более новый. Повторные попытки сохраняют
  эпоху восстановления. Клиент применяет составное обновление с перекрывающейся
  базой, а настоящий разрыв последовательности по-прежнему запрашивает новый снимок.
- Начальный вид большой карты показывает точку подключения в читаемом масштабе;
  «Обзор» вмещает весь этаж. Интервалы между маркерами увеличены, связи приглушены,
  фильтры подписаны, выбранное устройство вынесено в отдельную строку.

CI также выявил устаревшие предположения тестов: радиопередача теперь завершается
асинхронно и требует физической сети; исследовательская база принадлежит настоящему
R&D-серверу. При параллельной загрузке учебной арены его поздняя инициализация может
быть отложена: тесты ограниченно ждут базу этого сервера. Проверки приёма, изоляции,
глушения и начисления очков сохранены.
Тест сопротивления скелета учитывает фактический сезонный модификатор Halloween.
Загрузка прошивки в непривязанный исследовательский терминал оставляет диск у игрока;
астросенсор без базы исследований не тратит лимит начисления.
Обработчик удаления источника радиосигнала допускает поздний вызов после очистки
подписок и повторную очистку; ссылки на удаляемый интерком и говорящего освобождаются.

## Границы проверки

После установки BYOND 516.1688 выполнена серверная сборка: 0 ошибок, 0 предупреждений.
Прошли все 396 серверных регрессий Netrun и 224 frontend-теста в 30 наборах.
DreamChecker завершился с 0 diagnostics; ESLint, TypeScript и production-сборка TGUI
прошли. Карта проверена в браузере при 1040×840 и 760×680, включая общий обзор,
без ошибок JavaScript. Все восемь сценариев падений из присланного CI прошли отдельные
проверки после исправлений. Повторный запуск загрузки учебной арены вместе с
инженерными событиями завершился успешно, без runtime; поздняя инициализация больше
не сбрасывает подготовленные питание и привязку тестовой исследовательской консоли.

Процент ускорения после изменений пока не измерен. Показанные сокращения вызовов
следуют из изменённых алгоритмов, а не из нагрузочного прогона с реальными клиентами.
Полная начальная проекция и реальное изменение инфраструктуры всё ещё требуют
обхода графа; физические таблицы активных источников занимают память пропорционально
числу сохранённых источников и размеру достижимого графа. Это остаточная стоимость,
которую нужно оценивать следующим серверным профилем, а не объявлять устранённой.

Для следующего профиля сравниваются одинаковые интервалы: 1/2/8 открытых карт,
два оператора одного терминала, поток машинных пакетов, закрытие UI, удаление деки,
пустые ЛВС и пробуждение защиты. В статистике SSnetrun `Pub` показывает число
публикаций/уникальных адресов/уведомлений ЛВС; `topology.route_snapshot_copies` — число собственных
копий дерева. Значения накопительные, для сравнения берётся разница за интервал.
